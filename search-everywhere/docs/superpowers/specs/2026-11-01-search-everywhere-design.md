# Search Everywhere 设计

日期：2026-11-01

> 文件搜索的查询、排序、最近文件与高亮已被 `2026-11-02-file-search-wasm-design.md` 取代；其余条款继续有效。

## 目的

做一个 VS Code 插件。用户双击 Shift，打开一个搜索面板，在整个工作区以及 Java 项目的外部依赖包里搜索。依赖包不是单独的功能，而是同一套搜索的范围扩展。

插件显示名称为 Search Everywhere。贡献的命令标题、面板状态和空输入提示使用中文。文件名、代码和命令 ID 保持原样。

## 范围

一次查询同时覆盖：

- 工作区文件名
- 工作区文件内容
- 工作区符号，以及依赖包中的类名
- VS Code 命令
- 后缀过滤，对工作区和依赖包使用同一套规则

依赖来自 Maven 和 Gradle，包含多模块，包含 compile、runtime、test 的传递依赖。源码只使用本地已经存在的 `*-sources.jar`，不下载缺失的源码包。

以下不做：

- 不反编译方法体，不搜索 `.class` 里的字符串
- 不修改用户的项目文件
- 不增加单独的「依赖」标签
- 空查询不列出最近文件
- 不解析 Maven / Gradle 以外的构建工具

## 架构

搜索界面是一个 `WebviewPanel`，开在当前编辑器组并获得焦点。VS Code 没有居中模态窗口 API，所以它不是独立的系统窗口。关闭后面板销毁，下次打开重新创建。面板只负责输入框、标签、结果列表和键盘，通过消息把查询发出去、把结果画出来。

其余模块：

| 模块 | 职责 |
| --- | --- |
| 查询解析 | 把输入拆成搜索词和后缀列表 |
| 搜索协调器 | 按标签调用提供者，丢掉过期结果，合并、排序、限额 |
| 工作区提供者 | 文件名索引和内容搜索 |
| 符号与命令提供者 | 工作区符号、依赖类名、命令标题和命令 ID |
| Classpath 解析器 | 解析每个 Maven / Gradle 模块的传递依赖，得到 JAR 和已存在的 sources jar |
| 依赖索引 | 保存类名、条目路径、文本缓存和 `.class` 声明 |
| 结果打开器 | 打开工作区文件、JAR 内源码或只读声明，或执行命令 |

协调器在存在后缀过滤时只保留匹配的文件和符号，不返回命令。文件提供者和符号提供者都读取依赖索引。

激活事件为 `onStartupFinished` 和 `onCommand:searchEverywhere.show`，这样双击 Shift 在启动后可用。

## 查询、标签和键盘

### 查询解析

按空白拆成词。一个词只有在整词是 `.ext`、`*.ext`，或由逗号连起来的这类词（`.java,.xml`、`*.java,*.xml`）时，才是后缀过滤。后缀比较忽略大小写。

`User.java` 整词保留为搜索词。`User .java` 的搜索词是 `User`，后缀是 `.java`。

去掉后缀后，剩余的词都要命中，大小写不敏感，词与词之间不要求相邻。一条结果归入它能达到的最高一档。

- 文件名完全匹配：带后缀的文件名，或不带后缀的文件名，与唯一的那个搜索词相同。多个搜索词时没有完全匹配这一档。
- 文件名前缀匹配：不带后缀的文件名以唯一的搜索词开头。多个搜索词时没有前缀这一档。
- 包含匹配：文件名或相对路径包含每一个搜索词。
- 类名使用同一套三档，对象换成简单类名和全限定名。完全匹配和前缀匹配看简单类名。
- 命令的完全匹配、前缀匹配、包含匹配看标题和命令 ID。

只有后缀、没有搜索词时，列出该后缀的文件名和依赖类名，不搜索内容，也不调用工作区符号提供者。输入为空时不搜索，面板提示：输入关键词，用 `.java` 或 `*.java,*.xml` 按后缀过滤。

`.java` 命中工作区和源码包里的 `.java`，也命中依赖里的类。`.class` 只命中类文件路径。其他后缀按真实文件后缀匹配。

### 标签

- **全部**：按文件名、符号、命令、内容的顺序分四组。每组最多 8 条。超出时提示还有结果，并让用户切换到对应标签。
- **文件**：文件名在前，内容在后，每组最多 100 条。
- **符号**：工作区符号和依赖类名在同一个列表，最多 100 条。依赖行标出 JAR 文件名。只有后缀、没有搜索词时，这一标签只列出匹配后缀的依赖类名。输入为空时不列出。
- **命令**：按标题和命令 ID 匹配，最多 100 条。找不到标题时，标题位置显示命令 ID。没有搜索词时，这一标签为空。

同一档内部，工作区结果排在依赖包结果前面。内容结果没有更细的质量差别，因此工作区的内容命中全部排在依赖包的内容命中前面；各自内部保持搜索工具原来的顺序。

每行显示标题、路径或命令 ID、来源（工作区或 JAR 文件名）。内容命中额外显示行号和该行文本。文本被截断的命中标上「文本不完整」。

### 键盘

双击 Shift 执行 `searchEverywhere.show`。命令面板中的标题是「Search Everywhere: 搜索」，用户可以自行改键。面板已经打开时，双击 Shift 不重复打开。

上下键移动选中项，回车或点击打开并关闭面板，Esc 关闭。Tab 和 Shift+Tab 在四个标签之间切换，焦点留在面板里。

文件名、符号和命令随输入立即更新。内容搜索在停止输入 200 毫秒后开始。新的输入使上一次查询失效，晚到的旧结果被丢弃。

## 数据流

### 工作区

激活时建立文件名索引，文件增删改时更新。索引尊重 `files.exclude`、`search.exclude` 和 `.gitignore`。文件名搜索只查这份索引。

工作区内容搜索调用 VS Code 自带的 ripgrep，最多取 100 条。依赖文本在建索引时写入索引，查询只读这份索引，不在每次输入时解压 JAR，也不对依赖文本再跑 ripgrep。这与 IntelliJ 相同：依赖进入工程时建索引，Search Everywhere 只查索引。依赖文本最多取 100 条。合并进「文件」标签的内容组时再截到 100 条，工作区在前。只有后缀、没有搜索词时不运行内容搜索。多个搜索词要求同一行同时包含每一个词，大小写不敏感。

有搜索词时，符号搜索调用 `vscode.executeWorkspaceSymbolProvider`，再并上依赖索引中的类名。命令来自已安装扩展的 `contributes.commands` 标题，以及 `vscode.commands.getCommands` 返回的命令 ID。

### 依赖解析

对每个工作区文件夹查找 Maven / Gradle 模块，包括多模块。优先使用项目中的 `mvnw` / `gradlew`，否则使用系统路径上的 `mvn` / `gradle`。

Gradle 用插件自带的外部 init script 打印已解析 JAR 路径，不把脚本写入用户项目。Maven 取 compile、runtime、test 三个 scope。Gradle 取 `compileClasspath`、`runtimeClasspath`、`testCompileClasspath`。同一个 JAR 路径只索引一次。本地已存在的 `*-sources.jar` 记入来源；不存在就留空。

监听这些文件，变化后等待 1 秒再重建索引：`pom.xml`、`build.gradle`、`build.gradle.kts`、`settings.gradle`、`settings.gradle.kts`、`gradle.properties`、`gradle/libs.versions.toml`。另有命令「Search Everywhere: 刷新依赖索引」。重建完成前，搜索仍使用上一份索引。

### 依赖索引

索引放在工作区存储中。每个 JAR 以路径、修改时间和大小作为缓存键，三者都没变则不重读。

- `.class`：保存全限定名、简单类名、JAR 内路径，以及声明所需的类头和方法签名。不索引字节码里的字符串。
- 源码包中的 `.java` 按文本索引。其他条目不含 NUL 字节的按文本索引，含 NUL 字节的只索引路径。`.class` 只索引类名、路径和声明，不索引字节码里的字符串。文本留在依赖索引里供查询，查询路径不再打开 JAR。
- 单个文件超过 1 MB，或一个 JAR 抽出的文本超过 50 MB：类名和路径仍然完整保留，文本只保留到上限，对应命中标记「文本不完整」。

## 打开结果

工作区的文件名命中直接打开该文件。内容命中打开同一文件并跳到命中行。

依赖中的源码和文本通过 `TextDocumentContentProvider` 打开。文档没有写回 JAR 的保存逻辑，编辑器里的修改不会进入依赖包。`.java` 按 Java 显示，其他文本按后缀选择语言。内容命中跳到那一行。

类名命中在有源码时，把 `.class` 的 JAR 内路径换成 `.java` 再去 sources jar 里找。内部类先去掉 `$` 及其后面的名字，打开外部类文件，例如 `com/foo/Outer$Inner.class` 对应 `com/foo/Outer.java`。在该文件中查找与目标简单类名相同的 `class`、`interface`、`enum`、`record` 或 `@interface` 声明，找到第一处就定位，找不到就停在文件开头。同一个类同时有 `.class` 和源码时，打开源码。

只有 `.class` 时，用同一个内容提供者打开声明，修改不会写回 JAR。内容依次是：

- 包名
- 类头：种类（class、interface、enum、record 或 annotation）、类名、继承类、实现的接口
- 方法签名

方法签名优先使用 class 文件中的泛型签名；没有泛型信息时使用原始类型。声明不包含方法体，也不包含字段。内部类只展示它自己的声明。类文件能解析出路径类名、但读不出方法签名时，声明中写「无法读取方法签名」。

命令命中执行对应命令。

回车或点击都会打开结果并关闭搜索面板。

## 错误处理

找不到 `mvn` / `gradle`、构建失败，或一次解析超过 3 分钟，都视为依赖解析失败。工作区文件名、内容、符号和命令继续可用。

- 已有上一份索引：状态为「依赖解析失败，仍使用上一份索引」。
- 还没有索引：状态为「依赖包暂不可搜」。
- 只有一部分模块失败：成功的模块照常进入索引。

读不了的 JAR 跳过，其余继续。面板只显示数量，例如「3 个依赖包无法读取」。解析器输出、被跳过的 JAR 和类文件解析失败写入输出通道 `Search Everywhere`。

内容搜索失败时，文件名、符号和命令照常显示，内容组显示「内容搜索失败」。

文件已删除、JAR 条目不存在或命令执行失败时，弹出错误信息，面板保持关闭。没有打开文件夹时只提供命令搜索，状态为「没有打开的文件夹」。索引重建期间状态为「正在更新依赖索引」。

## 测试

单元测试不启动 VS Code，覆盖：

- 查询解析：`User .java`、`*.java,*.xml`、`User.java` 作为搜索词、只有后缀、空输入
- 排序：完全匹配、前缀匹配、包含匹配，同档时工作区在依赖包之前
- 限额：「全部」每组 8 条；「文件」「符号」「命令」各最多 100 条。内容组合并后工作区命中在前
- 后缀：`.java` 命中源码和依赖类，`.class` 只命中类路径，有后缀时不返回命令
- 后发查询先返回时，先发查询的结果被丢弃
- 内容搜索失败时，文件名和符号结果仍在，内容组为失败状态

依赖索引用准备好的 Maven / Gradle 输出做夹具，测试中不执行真实构建。夹具 JAR 包含 `.class`、`.xml` 和 sources jar。断言类名、文本命中、声明中的方法签名，以及有源码时打开 `.java`。缓存键未变时不重读。超过 1 MB 的文件和超过 50 MB 的 JAR 文本保留类名，并标成文本不完整。损坏的类文件保留由路径得到的类名。

在 VS Code 中手工确认：双击 Shift 能打开面板；四个标签和回车打开符合本文规则；没有 `mvn` / `gradle` 时工作区搜索仍可用且状态正确；多模块项目能搜到传递依赖。双击 Shift 能否被编辑器交给插件，只做手工确认。
